# Step limits for a coding agent

**Question.** Does raising a coding agent's step limit from 20 to 40 tool calls increase the share of repository tasks it solves?

**Design.** 150 tasks sampled at random from a public benchmark of repository-level bug fixes. Each task is run once in each condition with a pinned model snapshot and identical prompts, tools and harness; only the step limit differs. Each run starts from a fresh container built from the task's snapshot. The hidden tests are not present in the container. Run order is randomized, with conditions interleaved.

**Outcome.** Whether the task's hidden tests pass after the run, recorded for every assigned run. Runs that crash or reach the step limit count as unsolved.

**Analysis (pre-specified).** Paired difference in solve rates (40 minus 20) across the 150 tasks, with standard errors clustered by task; the sample size comes from a recorded power calculation. Token use and cost are reported by condition. The claim concerns raising the step limit for this model and harness, including the extra compute it allows.
