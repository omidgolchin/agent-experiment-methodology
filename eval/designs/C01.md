# A search tool for a question-answering agent

**Question.** Does giving a question-answering agent a search tool over a fixed document collection improve its accuracy on multi-hop questions?

**Design.** 200 questions sampled at random from a public multi-hop question-answering dataset with gold answers. The dataset's document collection is frozen as a local index; the agent has no web access. Every question is run in both conditions with a pinned model snapshot, temperature 0, the same limit of 10 model turns and the same maximum output length. The prompts are identical except that the treatment prompt describes the `search` tool, which only the treatment agent can call. Run order is randomized and the two conditions are interleaved.

**Outcome.** Exact match with the gold answer, scored by script. Unparseable outputs and runs that reach the turn limit are scored as incorrect in both conditions, and these rates are reported by condition.

**Analysis (pre-specified).** The primary estimand is the difference in accuracy (treatment minus control) across these 200 questions, analyzed as paired data with standard errors clustered by question. A power calculation, recorded with its inputs, shows 80% power for a 6-point difference. The tool's description, the retrieved text and the tokens they add are part of the treatment and are reported as such; the claim is limited to this model and to questions like these.
